# Source coverage reporting

Run `npm test` with the pinned Node 24/npm runtime. The pipeline runs the existing native Node suite once with one worker, then remaps its actual V8 captures through exact `c8@12.0.0`. Native test failures and the native global 60% lines, branches and functions thresholds remain blocking.

This frontend declares `componentEnvironment: 'node'` in `scripts/coverage-scope.cjs`. Its real Node server-view tests own every runtime `src/**/*.ts` and `src/**/*.tsx` file. c8 includes unimported files with `--all`; every inventoried source must appear in the report. The corrected report must reach 60% global lines, branches and functions and 60% lines for each file, with no source exception. A low source score fails the command; it is not replaced by a score from another environment.

TypeScript declarations are also inventoried and hashed. A strict TypeScript AST classifier identifies files containing only erased type aliases, interfaces, type imports or type exports. Parse errors block classification; a value import, effect import, function, class, enum, value or other statement prevents a runtime source from being classified as type-only. Such non-executable records remain visible with LF/FNF/BRF zero, rather than fabricated executed hits. Generated `.d.ts` declarations are separately identified in provenance. Original c8 reports remain byte-for-byte under `coverage/source-mapped/c8-raw/` before official Istanbul reporters write the normalized report; no executable source is exempted from the thresholds.

`coverage/lcov.info` is the corrected primary report for CI and is byte-identical to `coverage/source-mapped/lcov.info`. Native LCOV, stdout, stderr, run status and raw V8 captures remain under `coverage/native/`. Source, map and input hashes and gate results are recorded in `coverage/source-mapped/provenance.json`. Previous reports move to `coverage/history/`. The driver archives native LCOV before removing it from the primary path. Missing maps, missing embedded source, changed source or invalid reports prevent primary publication. Native failure still fails the pipeline even when remapping succeeds.

The shared CI uploader explicitly uses the primary report with report discovery disabled. Raw audit files remain in the local/CI workspace; this change adds no persistent CI artifact upload or external raw-data upload. Package audit and publication gates remain separate and unchanged.
